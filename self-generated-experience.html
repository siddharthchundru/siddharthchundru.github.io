What Should a Robot Practise?

Goal selection, behavioural repertoire and recovery in self-improving policies.

Research question

A goal-conditioned agent starts from a few demonstrations that cover only part of its world, then improves through a fixed budget of its own practice. With the learner, the demonstrations and the budget held fixed, how does the choice of what to practise affect its competence on the tasks it was shown, its behavioural repertoire (the distinct ways it can solve the same task), and its recovery when the solution it relies on is blocked?

Why it matters

When a demonstration-pretrained policy is improved with task reward, its behavioural modes tend to collapse onto a single solution (Longhini et al., 2026; Ibn Hamid et al., 2025). Published remedies add an explicit diversity objective, and deployment-time recovery methods assume the policy still has alternatives to fall back on. This project asks whether the goals an agent chooses to practise can preserve those alternatives on their own, and whether a preserved repertoire actually buys recovery.

Design

The environment is a custom PointMaze layout in MuJoCo in which key start–goal pairs have exactly two routes, one clearly shorter. Demonstrations cover both routes. The learner is goal-conditioned supervised learning (GCSL) with a categorical action head, which, unlike a Gaussian head, can represent two routes at once. It is identical in every condition; only the rule for choosing practice goals varies:

  • Demonstrations only, with matched training steps.
  • Random actions.
  • Task-directed practice on the demonstrated goals.
  • Frontier novelty: practising the least-visited goals the agent has already reached, following MEGA.

A re-learning control trains a fresh learner on each run's final data, to test whether any advantage lies in the collected data or in the active loop that collected it.

Evaluation

Three primary measures: success on the demonstrated tasks; repertoire, counted as the number of distinct routes that each account for a meaningful share of successful rollouts; and success after each agent's most-used route is blocked, both immediately and after a common adaptation procedure. Hypotheses, endpoints and analysis will be pre-registered on OSF after a pilot. Clear null results, shown by equivalence tests, count as answers.

Build process

The code is built with Claude Code in a two-agent workflow: one agent implements each stage, and a separate agent audits it for mismatched budgets, goal leakage and extra gradient updates. Audit reports are committed to the repository.

Status: specification, literature review and maze layouts with planner tests are complete. The simulation harness is in progress. No experimental results yet.
